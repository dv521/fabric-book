Codex CLI 实战教程 · 30 个案例

一个案例 = 一个功能　由浅入深　全部照抄可用　·　dv面料手记 · 工具

先记三条铁律，比记命令重要。

这套命令全部围绕三个真实目录：站点 ~/deploy-fabric-book、资料 ~/Documents/面料资料、归档 …/归档。装好独立版后终端里输 codex 即可。

铁律 1先只读，后动手
铁律 2永远带 -C 目录
铁律 3改完必看 git diff

第一层 · 入门：能对话、能读、能改

案例 1 · 交互模式

第一次对话：让它体检，不动手

刚装好，先看它能不能读懂你的站点。

cd ~/deploy-fabric-book
codex

进去打：

只读，不要改文件。告诉我这个仓库有几类文件、各多少个，以及首页用的是哪个 html。

你会看到：一份文件清点 + 指认 index.html。

交互里 / 看命令，Ctrl+C 中断，Ctrl+D 退出。
案例 2 · 精准提问

问一个具体答案：比翻文件快

忘了某条红线写在哪。

codex exec -s read-only -C ~/deploy-fabric-book "「绝对化词禁用」这条规则写在项目里哪个文件？把原文那一行引出来。"

你会看到：文件路径 + 原文行。

问「在哪、原文是什么」，不问「你觉得该怎么写」。前者可核查，后者容易编。
案例 3 · 第一次动手

改一个文件的一段文案

某页文案要改口径。

codex exec -s workspace-write -C ~/deploy-fabric-book "打开 tools/price-compare.html，把页面标题里的『报价换算』改成『每平方米单价换算』，只改这一处，其余不动，改完列出 diff。"

验收：

cd ~/deploy-fabric-book && git diff
指令必须写清三件事：哪个文件、改哪一句、其它不动。少一样，它就会顺手多改。

第二层 · 单次执行：批处理与产出

案例 4 · 导出 CSV

统计章节字数：让它算，不要它说

想看 36 章各多少字，手数太慢。

codex exec -s workspace-write -C ~/deploy-fabric-book "统计 book/ 下每个 html 的正文汉字数（去掉标签和脚本），输出 csv 到 /tmp/章节字数.csv，列为 文件名,字数，按字数降序。"

你会看到：/tmp/章节字数.csv，可直接用 Numbers 打开。

让它产出文件而不是在屏幕上念数字——文件能核对，屏幕上的数字不能。
案例 5 · 批量替换

限定范围才安全

全站把旧参数改成新值（例：门幅 142 改 143）。

codex exec -s workspace-write -C ~/deploy-fabric-book "只在 book/ 和 daily/ 两个目录里，把『142 厘米』改成『143 厘米』，其它目录不要动，改完报告每个文件改了几处。"

验收：

git diff --stat
git diff | grep -c "143 厘米"
批量替换最怕「顺手全文替换」。写死目录范围 + 要它报处数，是唯一可靠的约束。
案例 6 · 新建页面

按现有风格加一个工具页

想加「退货分类卡」小工具页。

codex exec -s workspace-write -C ~/deploy-fabric-book "照 tools/quote-sheet.html 的结构、配色、字体，新建 tools/return-card.html：标题『退货分类卡』，四个按钮（钻绒/破洞/跑绒/色差），点一下显示对应处理动作。样式必须和现有页面完全一致，不要引入外部库。"

验收：

grep -c "noindex" tools/return-card.html
让它照抄一个现成文件，比描述风格有效十倍。

第三层 · 检查与回退：让改动可控

案例 7 · 红线扫描

发布前自检

发站之前，确认没有微信、二维码、http:// 泄漏。

codex exec -s read-only -C ~/deploy-fabric-book "扫描所有 html，找出出现以下词的页面并列出文件名与那一行：微信、扫码、二维码、http://、加我、扣1。只报告，不要改。"
这类检查每周跑一次，比出事再查省事。
案例 8 · 审与退

审改动、回退、第二天续做

它改完你不放心。

cd ~/deploy-fabric-book
codex review              # 让它自己挑这次改动的毛病
git diff --stat           # 看改了哪几个文件
git checkout -- 文件名     # 单文件撤回
git reset --hard HEAD     # 全撤回（慎重）

接第二天：

codex resume --last
改之前先 commit 一次，退路就永远在。

第四层 · 进阶：隔离、看图、进管道

案例 9 · worktree

大改动先隔离，不脏主分支

要重构 tools 的公共样式，改坏了不能影响线上。

codex exec --worktree -C ~/deploy-fabric-book "把 tools 下所有页面重复的内联样式抽成 tools/ui.css，页面改为引用它，视觉不得变化。"

你会看到：它在一个新的 git worktree 里干活，你的主目录一动不动。

git worktree list
--worktree 是你敢让它动大手术的前提。
案例 10 · 看图

发一张截图让它找问题

手机上看某页按钮被截断，说半天说不清。

codex exec -s read-only -C ~/deploy-fabric-book -i ~/Desktop/手机截图.png "这个页面在 390 宽的屏幕上按钮被截断，找出是哪个样式导致的，给出修改方案，先不要改。"
UI 问题一张图胜过五百字。它看得到像素，就看得到你的问题。
案例 11 · 进管道

把结果喂给脚本

想接进每天的检查流程。

codex exec --json -s read-only -C ~/deploy-fabric-book "检查是否存在空的 html 文件、以及没有 viewport 的页面，输出结构化结果" > /tmp/check.json

再用 python 读：

/usr/bin/python3 -c "
import json
d=json.load(open('/tmp/check.json'))
print(json.dumps(d, ensure_ascii=False)[:500])
"
--json 让它变成一个可以被程序调用的函数，不再只是聊天工具。

第五层 · 高手：配置档、外挂、定时

案例 12 · 配置档

快活和慢活分开

日常小改用快模型，深度分析用高思考。新建 ~/.codex/slow.config.toml：

model = "deepseek-flash"
model_reasoning_effort = "high"

用的时候：

codex -p slow exec -C ~/deploy-fabric-book "分析首页在手机上加载慢的原因，给出前三条"
-p 是叠加在主配置上的补丁，不动主配置就能换档。
案例 13 · MCP

接外部工具

让它直接查某个服务，而不是靠你复制粘贴。

codex mcp list
codex mcp add 名称 -- 启动命令
codex mcp get 名称
codex mcp remove 名称
MCP 是「给它装外挂」。先 list 看已有什么，再加新的。
案例 14 · 定时

每天自动跑一次检查

睡前不想手动查站，让机器自己查。脚本 /tmp/daily_check.sh：

#!/bin/zsh
cd ~/deploy-fabric-book || exit 1
codex exec --json -s read-only -C . "检查是否有页面缺 viewport、是否出现微信或二维码字样，输出 json" \
  > ~/Documents/面料资料/归档/check_$(date +%F).json
codex exec 天生适合被定时任务调用：跑完就退出，不留交互。

第六层 · 常被忽略但很有用（案例 15–22）

案例 15 · 多目录

一次改两个目录

站点和资料库要同时改（比如总则改了，站点文案跟着改）。

codex exec -s workspace-write -C ~/deploy-fabric-book --add-dir ~/Documents/面料资料 "把总则里的『130–135 字』同步到 tools/codex.html 的对应说明里"
默认只能写 -C 那一个目录；要碰别处必须 --add-dir 显式放行。
案例 16 · 固定输出格式

让它按你的表格输出

要接进表格或脚本，格式必须固定。先写一个 schema 文件 /tmp/ch.json：

{"type":"object","required":["file","chars"],
 "properties":{"file":{"type":"string"},"chars":{"type":"integer"}},
 "additionalProperties":false}

再跑：

codex exec -s read-only --output-schema /tmp/ch.json -C ~/deploy-fabric-book "输出 book/ch01.html 的字数"
--output-schema 保证它不会自由发挥，字段名错一个就报错，适合接自动化。
案例 17 · 多任务并行

同时开几条活，来回切

一条在改站点、一条在整理资料，不想互相打断。

codex agents          # 命令中心：看所有会话、切换
codex fork --last     # 从上次的会话岔出一条，原会话不动
codex queue --thread <会话ID> --message "改完顺手跑一次检查"
fork 是「同一份上下文，两种走法」，比复制粘贴上下文省事。
案例 18 · 清理

会话多了要归档

codex archive --last        # 归档最近一条
codex archive <会话ID>      # 指定归档
codex unarchive <会话ID>    # 取回
codex delete <会话ID>       # 永久删除（不可恢复）
配置里 autoArchiveAfterDays = 14，两周不用的会话会自动归档，不会丢但也不碍眼。
案例 19 · 项目规矩

把红线写进 AGENTS.md，让它别再犯

每次都在指令里重复「不许出现微信、二维码」太累。在仓库根目录建 AGENTS.md：

# 本站红线（每次改动都必须遵守）
- 页面不得出现：微信、二维码、扫码、http://、手机号
- 不得使用绝对化词：绝不、100%、第一、最好
- 改任何页面必须保留 noindex,nofollow
- 标准号与经验值必须标注出处
它每次进这个目录都会先读这份文件。规矩写一次，省一百次叮嘱。
案例 20 · 带标准的审查

审查时给它判据

codex review "重点看三件事：有没有出现微信或二维码；有没有绝对化词；新增页面有没有 noindex。按严重程度排。"
不给判据，它就按通用代码规范挑毛病；给了判据，它才按你的规矩挑。
案例 21 · 本地模型

不想走网络时

codex exec --oss --local-provider ollama -C ~/deploy-fabric-book "这段 css 是做什么的"
需要本机装了 Ollama 或 LM Studio。能力弱一些，但断网可用、内容不出本机。
案例 22 · 维护

补全、更新、体检

codex completion zsh      # 生成命令补全（写进 ~/.zshrc 后 tab 能补）
codex update              # 升级到最新版
codex doctor              # 体检：配置、登录、沙箱、磁盘
出怪问题时，先跑 doctor，九成能看出是哪一层坏了。

第七层 · 真正进阶的八个（案例 23–30）

案例 23 · 管道输入

把文件直接喂给它，不用复制粘贴

一段日志、一份 csv、一篇文章，不想选中复制进对话框。

cat /tmp/章节字数.csv | codex exec -s read-only -C ~/deploy-fabric-book "这份 csv 里字数最少的三章是哪三个？"

echo "这段文案有没有绝对化词：全网最低，绝不掉绒" | codex exec -s read-only -C . -
提示词用 - 就从标准输入读。配合 cat、grep、git diff 输出，一条链就完成“取样→判断”。
案例 24 · 非交互续跑

不打开界面，接着上次那条活干

codex exec resume --last "把刚才列出的问题按严重程度排序，先修前两条"

codex exec fork --last "换个做法：不动样式，只加一个开关"
resume 是接着干，fork 是岔出去试另一种做法——原会话都不动。适合晚上挂一条长任务、早上接着改。
案例 25 · 交互内命令

进去以后用斜杠管自己

在 codex 交互模式里，输 / 看全部，最常用的四个：

/compact     上下文太长、开始答非所问时压缩
/model       临时换模型
/diff        看它这次到底改了什么
/init        给这个目录生成一份初始 AGENTS.md
会话越聊越慢、越聊越笨，八成是该 /compact 了，不是模型不行。
案例 26 · 全局规矩

跨项目生效的规矩文件

项目里有 AGENTS.md，全局还有一份 ~/.codex/AGENTS.md——所有目录都先读它。

# ~/.codex/AGENTS.md
- 一律用中文回答，不要英文段落
- 结论先行，再给数字，最后给依据
- 不确定就说不确定，不要编标准号
- 改动前列 diff，改完报处数
项目文件管“这个仓库的规矩”，全局文件管“我的说话方式”。两层叠加，一次写好长期生效。
案例 27 · 插件

让它直接产出 PDF、表格、PPT

本机已装好这几个官方插件（codex plugin list 可查）：documents、pdf、spreadsheets、presentations、visualize。

codex exec -s workspace-write -C ~/Documents/面料资料 "把 总则.md 里「三 录音与出片」整节做成一页 A4 PDF，输出到 ~/Desktop/出片规范.pdf"

codex exec -s workspace-write -C ~/Documents/面料资料 "把 口播/数据台账.csv 做成一张折线图，标出完播率最高的三条"
这是 Codex 比你想象的更有用的地方：不只是改代码，还能出物料。装新插件用 codex plugin add。
案例 28 · 手机遥控

人在外面，用手机让电脑干活

codex remote-control start     # 起一个带远程控制的守护进程
codex remote-control pair      # 生成一次性配对码
codex remote-control stop      # 用完关掉
实验功能。配对码是一次性的，用完就 stop，别长期开着——这是唯一能从外部指挥你电脑的通道。
案例 29 · 长任务

跑一小时也不怕断线

nohup codex exec -s workspace-write -C ~/deploy-fabric-book \
  "给全部 36 章补上「本节要点」小结，逐章改，改完输出清单" \
  > /tmp/long.log 2>&1 &

tail -f /tmp/long.log     # 随时看进度
长任务用 nohup … & 挂后台 + 日志文件。手机断网、电脑合盖都不影响（合盖需插电）。
案例 30 · 成本与安全

看得见的 token，看得见的权限

每次 exec 结尾都会打印 tokens used——那就是这次花的量。三条省钱省心的习惯：

codex exec --ephemeral -s read-only -C . "一句话回答：首页标题是什么"   # 一次性任务，不存会话
codex exec -c model_reasoning_effort="low" -C . "把这段文案改得更口语"   # 小活用低思考
codex sandbox -- rm -rf /tmp/test                                        # 危险命令先沙箱试
--approve-for-me 是「自动审批，但仍在沙箱内」；--dangerously-bypass-approvals-and-sandbox 是「拆掉所有防线」，永远不用。

附 · 参数速查

参数作用什么时候用
-C 目录指定工作目录每次都要
-s read-only只读先看、出方案
-s workspace-write只改当前目录真动手
--json结构化输出给脚本读
--worktree新 worktree 干活大改动
-i 图片附带截图UI 问题
-p 名称用配置档换思考深度
--ephemeral不存会话一次性任务
-c key=value临时改配置试参数
--add-dir 目录额外允许写的目录跨目录修改
--output-schema 文件强制输出结构接脚本、接表格
--oss用本机模型断网 / 不出本机
--trust信任当前项目不复述授权

附 · 三句最常用的话

codex exec -s read-only -C 目录 "问题，只报告不要改"
codex exec -s workspace-write -C 目录 "任务，只改这些文件，其余不动，改完列 diff"
cd 目录 && codex review && git diff
